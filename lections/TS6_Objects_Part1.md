## 1. Что такое объект

Объект — тип данных, который хранит набор **свойств** (properties). Каждое свойство — это пара **ключ: значение** (key-value pair): ключ — название, значение — то, что под этим названием лежит. Свойство без ключа или без значения не бывает.

Лектор дал две аналогии:

- **Человек.** У человека есть имя, фамилия, возраст, интересы. «Имя» — ключ, «Джон» — значение.
- **Ящик с коробками.** Большой ящик — объект. Внутри много коробок, на каждой этикетка (ключ), внутри содержимое (значение).

Лектор сказал, что в TypeScript/JavaScript «почти всё — объекты»: функции и массивы — это объекты, а методы строк и массивов — это функции, лежащие внутри объектов.

**Уточнение.** Это упрощение. Массивы и функции действительно объекты. А вот строки, числа и `boolean` — примитивы (primitive — простое значение, не объект). Вызвать у строки метод (`"abc".toUpperCase()`) можно потому, что движок на время вызова оборачивает её во временный объект `String`.

## 2. Создание объекта и доступ к свойствам

### Базовый синтаксис

```ts
const имяОбъекта = {
  ключ1: значение1,
  ключ2: значение2,
};

имяОбъекта.ключ1; // чтение значения через точку
```

- Объект пишется в фигурных скобках `{ }`.
- Ключ и значение разделяет двоеточие `:`.
- Свойства разделяются запятой `,`.
- Ключи называют в camelCase: `firstName`, `age`.
- Для самой переменной действуют те же правила, что и раньше: `const` или `let`.

### Пример

```ts
const person = { firstName: "John", lastName: "Smith", age: 37 };

console.log(person);           // { firstName: 'John', lastName: 'Smith', age: 37 }
console.log(person.firstName); // John
```

Перед ключами внутри объекта не пишут `let` или `const`: это не переменные, а свойства объекта. `let`/`const` относится к переменной `person`, которой присваивается весь объект.

Порядок свойств на работу кода не влияет. Лектор советует группировать связанные свойства (имя рядом с фамилией, адрес рядом с городом) — так объект проще читать.

**Уточнение.** «Порядок не важен» верно для доступа по ключу. Но `console.log` и `Object.keys` выводят ключи в определённом порядке: сначала ключи-целые числа по возрастанию, потом остальные в порядке добавления:

```ts
Object.keys({ b: 1, 2: "x", a: 1, 1: "y" }); // [ '1', '2', 'b', 'a' ]
```

## 3. Вложенные объекты

Значением свойства может быть другой объект. Чтобы добраться до вложенного значения, ключи перечисляют через точку.

```ts
const user = {
  id: 1,
  personalInfo: {
    name: "Alice",
    age: 30,
    address: { city: "Tbilisi", street: "Rustaveli" },
  },
};

console.log(user.id);                          // 1
console.log(user.personalInfo.address.city);   // Tbilisi
```

Так обычно выглядит ответ API: `response.data.user.address.city`. Разбирать такие цепочки придётся постоянно.

## 4. Ключи из нескольких слов и квадратные скобки

### Базовый синтаксис

```ts
const obj = { "ключ с пробелом": значение };

obj["ключ с пробелом"];   // доступ через квадратные скобки и строку
obj["обычныйКлюч"];       // так тоже работает, но через точку проще
```

Если в ключе есть пробел, его берут в кавычки. Обратиться к такому ключу через точку нельзя — только через квадратные скобки со строкой внутри.

```ts
const user = { name: "John", "likes birds": true };

console.log(user["likes birds"]); // true
console.log(user["name"]);        // John — работает, но смысла нет: есть user.name
```

Лектор: так делать можно, но лучше не надо — используйте camelCase (`likesBirds`).

**Про ключи с цифрами** (вопрос студента). Лектор: ключ должен что-то значить, `name1`/`name2` технически работают, но смысла в таких именах мало. Ключ, начинающийся с цифры (`1name: ...`) без кавычек, — синтаксическая ошибка.

**Уточнение.** Ключ, целиком состоящий из цифр, допустим: `{ 1: "a" }`. JavaScript превращает его в строку `"1"`. Именно так устроены массивы: индексы — это ключи `"0"`, `"1"`, `"2"`.

## 5. Изменение значения свойства

### Базовый синтаксис

```ts
obj.ключ = новоеЗначение;
obj["ключ с пробелом"] = новоеЗначение;
```

```ts
const user = { name: "John", "likes birds": true };

user.name = "Bob";
user["likes birds"] = false;

console.log(user); // { name: 'Bob', 'likes birds': false }
```

Объект объявлен через `const`, но менять его свойства можно: `const` запрещает присвоить переменной *другой объект*, а не менять содержимое этого.

Тип свойства менять нельзя. TypeScript вывел тип из начального значения, и строгая типизация действует на свойства объекта так же, как на обычные переменные:

```ts
const p = { name: "Jim", age: 20 };
p.age = "John";
// error TS2322: Type 'string' is not assignable to type 'number'.
```

## 6. Вычисляемые ключи

**Зачем.** Иногда название ключа заранее неизвестно — оно приходит из переменной: из ответа API или из логики программы («если пользователю меньше 18, добавить такое-то свойство»). Лектор отметил, что на практике это нужно редко.

### Базовый синтаксис

```ts
const obj = { [переменная]: значение };
```

Квадратные скобки вокруг имени **без кавычек** означают: «это не название ключа, а переменная; возьми её значение и сделай его ключом».

```ts
const key = "greatSkier";
const user = { name: "John", [key]: true };

console.log(user);            // { name: 'John', greatSkier: true }
console.log(user.greatSkier); // true
```

Главное отличие:

| Запись | Что означает |
|---|---|
| `[carModel]: ...` | значение переменной `carModel` станет ключом |
| `"carModel": ...` | ключ буквально называется `carModel` |

**Уточнение.** Если переменная объявлена как `let key: string` (то есть TypeScript не знает конкретное значение), тип объекта станет «любые строковые ключи» (`{ [x: string]: ... }`). TypeScript перестанет проверять, какие ключи реально есть. С `const key = "greatSkier"` TypeScript знает точное имя ключа и проверяет его.

## 7. Проверка наличия свойства: in и Object.hasOwn

### Базовый синтаксис

```ts
"ключ" in obj;              // true / false
Object.hasOwn(obj, "ключ"); // true / false
```

Название ключа в обоих случаях пишется **строкой в кавычках**.

```ts
const user = { name: "John", age: 30 };

console.log("age" in user);                     // true
console.log("occupation" in user);              // false
console.log(Object.hasOwn(user, "age"));        // true
console.log(Object.hasOwn(user, "occupation")); // false
```

Какой способ лучше? Лектор: для нас разницы нет, можно использовать оба.

**Уточнение.** Разница есть:

- `in` ищет ключ и в самом объекте, и в его прототипе (prototype — объект, от которого наш объект наследует встроенные методы вроде `toString`).
- `Object.hasOwn` проверяет только собственные свойства объекта.

```ts
console.log("toString" in user);              // true  — унаследован
console.log(Object.hasOwn(user, "toString")); // false — не собственный
```

Для проверки данных (например, «есть ли в ответе API поле `email`») надёжнее `Object.hasOwn`. `Object.hasOwn` появился в ES2022 (Node.js 16.9+). В `tsconfig` нужен `lib` не ниже `es2022`.

## 8. Методы объекта

**Зачем.** У человека в реальности есть не только характеристики, но и действия: говорить, платить, ходить. В объекте действия описываются функциями.

**Метод** — это функция, которая лежит в свойстве объекта. Отдельно стоящая функция — это функция; та же функция внутри объекта — метод. `toUpperCase` у строки и `map` у массива — тоже методы: функции внутри встроенных объектов, которые написали разработчики языка.

### Базовый синтаксис — три формы

```ts
const obj = {
  // 1. Полная запись
  имяМетода: function () { return ...; },

  // 2. Сокращённая запись (короче всего)
  имяМетода() { return ...; },

  // 3. Стрелочная функция
  имяМетода: () => ...,
};

obj.имяМетода(); // вызов — обязательно с круглыми скобками
```

### Пример

```ts
const p = {
  name: "Jim",
  greet1: function () { return "Hi from function"; },
  greet2() { return "Hi from shorthand"; },
  greet3: () => "Hi from arrow",
};

console.log(p.greet1()); // Hi from function
console.log(p.greet2()); // Hi from shorthand
console.log(p.greet3()); // Hi from arrow
```

Имя метода, как у любой функции, должно говорить, что он делает, и начинаться с маленькой буквы.

Без скобок метод не вызывается — вы получите саму функцию:

```ts
console.log(typeof p.greet2); // function
```

Заменить метод на значение другого типа нельзя, тип «функция» закреплён:

```ts
const p = { greet() { return "hi"; } };
p.greet = "hello";
// error TS2322: Type 'string' is not assignable to type '() => string'.
```

Формы 1 и 2 ведут себя одинаково. Стрелочная (3) отличается поведением `this` — см. [раздел 10](#10-this-и-стрелочные-функции).

## 9. Ключевое слово this

**Зачем.** Внутри метода почти всегда нужны другие свойства этого же объекта. Просто написать `name` внутри метода нельзя: `name` внутри метода и свойство `name` объекта — разные вещи. Для доступа к свойствам «своего» объекта используется `this`.

### Базовый синтаксис

```ts
const obj = {
  ключ: значение,
  метод() {
    return this.ключ; // this — объект, у которого вызвали метод
  },
};
```

### Пример

```ts
const person = {
  name: "Jim",
  eyes: "blue",
  age: 30,
  greetings() {
    return `Hello everyone, my name is ${this.name}, my eyes are ${this.eyes}`;
  },
};

console.log(person.greetings());
// Hello everyone, my name is Jim, my eyes are blue
```

Через `this` доступны любые свойства объекта, включая другие методы: `this.sayHi()`.

### Значение this вычисляется в момент вызова

Лектор особенно подчеркнул: пока метод не вызван, `this` ничему не равно. Значение определяется, когда выполняется `person.greetings()`, — и берутся **текущие** значения свойств:

```ts
person.name = "Bob";
console.log(person.greetings());
// Hello everyone, my name is Bob, my eyes are blue
```

**Уточнение.** Лектор объяснил это так: «после изменения имени это уже другой экземпляр того же объекта». Это неточно. Объект один и тот же, изменилось значение его свойства. `this.name` просто читает то значение, которое лежит в свойстве на момент вызова.

**Уточнение.** Точнее будет правило: `this` — это объект **слева от точки при вызове**. Отсюда два следствия, которые в лекции не прозвучали, но на практике встречаются.

Метод можно «одолжить» другому объекту, и `this` будет указывать уже на него:

```ts
const jim = { name: "Jim", viaThis() { return this.name; } };
const ann = { name: "Ann", viaThis: jim.viaThis };

console.log(ann.viaThis()); // Ann
```

Если вызвать метод без объекта слева, `this` потеряется:

```ts
const f = jim.viaThis;
f(); // TypeError: Cannot read properties of undefined (reading 'name')
```

Это частая ошибка, когда метод передают как колбэк (callback — функция, которую передают в другую функцию для вызова): `button.addEventListener("click", obj.method)`.

### Почему не писать person.name вместо this.name

Студент спросил: внутри метода работает и `person.name` — зачем тогда `this`? Лектор ответил, что так делать нельзя, и пообещал объяснить позже. Вот наглядная причина:

```ts
const jim = {
  name: "Jim",
  viaThis() { return this.name; },
  viaVar()  { return jim.name; },   // жёстко привязан к переменной jim
};

const bob = { ...jim, name: "Bob" }; // копия с другим именем

console.log(bob.viaThis()); // Bob — правильно
console.log(bob.viaVar());  // Jim — ошибка: метод смотрит на другой объект
```

`this` всегда указывает на объект, у которого вызвали метод. Имя переменной — на один конкретный объект.

## 10. this и стрелочные функции

**У стрелочных функций нет собственного `this`.** Внутри стрелочной функции `this` берётся от «родителя» — ближайшей обычной функции, внутри которой она написана.

### Стрелочная функция внутри обычного метода — работает

```ts
const p = {
  name: "John",
  intro() {
    const sayHi = () => `Hi, I am ${this.name}`; // this взят из intro
    return sayHi();
  },
};

console.log(p.intro()); // Hi, I am John
```

`intro` — обычный метод, его `this` равен `p`. Стрелочная `sayHi` своего `this` не имеет и берёт его у `intro`.

### Стрелочная функция как метод — не работает

```ts
const p = {
  name: "John",
  sayHi: () => `Hi, ${this.name}`,
};
```

Родитель стрелочной функции здесь — не объект (объект не функция), а код за его пределами. TypeScript сразу выдаёт ошибку. В файле-модуле (где есть `import`/`export`) она выглядит так:

```
error TS2532: Object is possibly 'undefined'.
```

**Уточнение.** Лектор сказал, что при запуске получится `undefined`. Результат зависит от среды:

| Где запускается | Результат `p.sayHi()` |
|---|---|
| Node.js, CommonJS (`.cjs`, обычный `ts-node`) | `Hi, undefined` — `this` равен `{}` |
| Node.js, ES-модуль (`.mjs`, `"type": "module"`) | `TypeError: Cannot read properties of undefined` |
| Браузер, обычный скрипт | `this` — это `window`, и `window.name` — пустая строка |

Вывод один: **не используйте стрелочные функции как методы, если нужен `this`.** Для методов берите сокращённую запись `метод() { }`.

**Про вопрос «а если вернуть `sayHi` без скобок».** Тогда метод вернёт саму функцию, а не результат её вызова:

```ts
const p = { introNoCall() { const sayHi = () => "x"; return sayHi; } };
console.log(typeof p.introNoCall()); // function
```

### this в обычной функции вне объекта

Вопрос в конце лекции: что будет, если написать `this` в обычной функции вне объекта? Лектор: `this` существует только внутри объекта, будет ошибка.

```ts
function hello() { return this.name; }
// error TS2683: 'this' implicitly has type 'any' because it does not have a type annotation.
```

**Уточнение.** Ошибка — от TypeScript в строгом режиме (флаг `noImplicitThis`): компилятор не знает, чем будет `this`. В JavaScript `this` в обычной функции существует всегда. При вызове без объекта в строгом режиме он равен `undefined`, и обращение `this.name` падает с `TypeError`.

## 11. Одинаковые имена: переменная, ключ, this

На лекции долго разбирали запутанный пример, где имя `name1` было одновременно внешней переменной, ключом объекта и переменной внутри метода. Суть:

```ts
let name1 = "John";              // внешняя переменная

const person = {
  name1: "Jim",                  // ключ объекта — к переменной отношения не имеет
  greetings() {
    let name1 = "Alice";         // локальная переменная метода
    return `${name1} / ${this.name1}`;
  },
};

console.log(person.greetings()); // Alice / Jim
```

- `this.name1` — всегда свойство объекта (`"Jim"`).
- `name1` без `this` — переменная. Сначала ищется внутри метода (`"Alice"`), потом снаружи (`"John"`).
- Локальная переменная с тем же именем, что и внешняя, «затеняет» внешнюю — это называется **shadowing** (затенение).
- `[name1]: "Jim"` (в квадратных скобках) создал бы ключ `John` — значение внешней переменной (см. [раздел 6](#6-вычисляемые-ключи)).

Совет лектора: **не называйте переменные и ключи одинаково.** Тогда такой путаницы просто не будет. Внешнюю переменную назовите, например, `outerName`, а локальную — `greetingName`.

## 12. Методы с параметрами

Метод принимает параметры так же, как обычная функция: с типами, через запятую.

```ts
const person = {
  name: "John",
  intro(greeting: string) {
    return `${greeting}, I am ${this.name}`;
  },
};

console.log(person.intro("Hello, Bob")); // Hello, Bob, I am John
```

Параметр используется внутри **без** `this`: это не свойство объекта, а обычный параметр функции. `this.greeting` здесь не существует.

Параметры могут быть опциональными или со значением по умолчанию — правила те же, что в лекции 5:

```ts
const d = {
  greet(toChange: boolean = false) {
    return toChange ? "changed" : "default";
  },
};

console.log(d.greet());     // default
console.log(d.greet(true)); // changed
```

Знак `?` и значение по умолчанию одновременно поставить нельзя:

```ts
greet(toChange?: boolean = false) { ... }
// error TS1015: Parameter cannot have question mark and initializer.
```

**Уточнение.** Лектор сказал, что параметр со значением по умолчанию «тогда неопциональный». Это неточно: параметр со значением по умолчанию при вызове можно не передавать — `d.greet()` компилируется без ошибок. `?` просто лишний, потому что опциональность уже обеспечена значением по умолчанию.

## 13. Object.keys, Object.values, Object.entries

Три встроенных метода превращают объект в массив, с которым можно работать как с обычным массивом: перебирать циклом, применять `map`, `filter` и т.д.

### Базовый синтаксис

```ts
Object.keys(obj);    // массив ключей
Object.values(obj);  // массив значений
Object.entries(obj); // массив пар [ключ, значение]
```

### Пример

```ts
const obj = { a: 1, b: 2, c: 3 };

console.log(Object.keys(obj));    // [ 'a', 'b', 'c' ]
console.log(Object.values(obj));  // [ 1, 2, 3 ]
console.log(Object.entries(obj)); // [ [ 'a', 1 ], [ 'b', 2 ], [ 'c', 3 ] ]
```

- `Object.keys` всегда возвращает массив **строк**: ключи объекта — строки.
- `Object.entries` возвращает вложенный массив: каждый элемент — пара `[ключ, значение]`.

### Подводный камень TypeScript: вернуться в объект по ключу

Лектор: взять ключи через `Object.keys`, пройти по ним циклом и прочитать `obj[key]` в JavaScript можно, а в TypeScript — нельзя. «Просто запомните».

```ts
const obj = { a: 1, b: 2 };
for (const k of Object.keys(obj)) {
  console.log(obj[k]);
}
// error TS7053: Element implicitly has an 'any' type because expression of type
// 'string' can't be used to index type '{ a: number; b: number; }'.
```

**Уточнение — почему так.** `Object.keys` возвращает тип `string[]`, а не `("a" | "b")[]`. TypeScript не может гарантировать, что в объекте нет других ключей, и не даёт индексировать объект произвольной строкой.

Как обойти:

```ts
// Вариант 1 — Object.entries: ключ и значение приходят вместе, индексировать не нужно
for (const [k, v] of Object.entries(obj)) {
  console.log(k, v); // a 1 / b 2 / c 3
}

// Вариант 2 — явно сказать компилятору, что k — ключ этого объекта
for (const k of Object.keys(obj)) {
  console.log(k, obj[k as keyof typeof obj]);
}
```

Вариант 1 проще и безопаснее. `keyof` и `as` на курсе ещё не проходили — вариант 2 для справки.

## 14. Типизация объекта

Лектор нарочно отложил типизацию до конца лекции. До этого все примеры были без явных типов — TypeScript выводил их сам.

### Базовый синтаксис

```ts
const имя: { ключ1: тип1; ключ2: тип2 } = { ключ1: значение1, ключ2: значение2 };

// или, когда свойств много, — в столбик:
const имя: {
  ключ1: тип1;
  ключ2: тип2;
} = {
  ключ1: значение1,
  ключ2: значение2,
};
```

### Пример

```ts
const person: { name: string; eyes: string; age: number } = {
  name: "Jim",
  eyes: "blue",
  age: 30,
};
```

- В описании типа тоже фигурные скобки.
- Указываются **все** ключи объекта с их типами, без значений.
- В типе свойства разделяют **точкой с запятой** `;`, в самом объекте — **запятой** `,`.
- Да, каждый ключ пишется дважды: в типе и в значении. Лектор пообещал показать более удобный способ на следующей лекции.

Если навести мышку на объект без явного типа, редактор покажет выведенный тип — TypeScript умеет выводить его сам. Лектор просит на курсе типы **не опускать**: мы учимся типизации, и есть вещи (опциональные свойства), которые без явного типа не описать.

Если в объекте не хватает обязательного свойства — ошибка:

```ts
const p: { name: string; occupation: string } = { name: "Jim" };
// error TS2741: Property 'occupation' is missing in type '{ name: string; }'
// but required in type '{ name: string; occupation: string; }'.
```

**Уточнение.** «Более удобный способ» — скорее всего, `type` или `interface`: описание типа выносится под отдельное имя и переиспользуется. Например, `type User = { name: string; age: number }`, потом `const u: User = {...}`.

## 15. Опциональные свойства

**Зачем.** При создании объекта не всегда известны все данные. Часть приходит позже — из API или из логики программы. Такие свойства могут быть, а могут и не быть.

### Базовый синтаксис

```ts
const obj: { обязательное: тип; необязательное?: тип } = { обязательное: значение };
```

Знак `?` после имени ключа **в типе** делает свойство опциональным. Лектор назвал это ещё одной причиной не опускать тип: опциональность можно указать только в нём.

### Пример

```ts
const user: { name: string; age: number; occupation?: string } = {
  name: "Jim",
  age: 30,
};

console.log(user);            // { name: 'Jim', age: 30 }
console.log(user.occupation); // undefined

user.occupation = "QA";       // добавили позже
console.log(user);            // { name: 'Jim', age: 30, occupation: 'QA' }
```

Опциональному свойству можно явно присвоить `undefined`, обязательному — нельзя:

```ts
const a: { address?: string } = { address: undefined };  // OK
const b: { address: string }  = { address: undefined };
// error TS2322: Type 'undefined' is not assignable to type 'string'.
```

Практический подход лектора: если объект может содержать 15 свойств, а известны пока 5, опишите в типе все 15, неизвестные сделайте опциональными, создайте объект из известных и добавляйте остальные по мере появления.

## 16. Опциональная цепочка (optional chaining)

**Зачем.** Нужно достать глубоко вложенное значение (`user.personalInfo.homeAddress.city`), но какого-то промежуточного объекта может не быть. Обращение к свойству у `undefined` или `null` падает с ошибкой даже в JavaScript. Можно проверять каждый уровень через `in`/`Object.hasOwn`, но это долго и громоздко.

### Базовый синтаксис

```ts
obj?.свойство
obj?.вложенный?.свойство
```

`?.` означает: «если слева `null` или `undefined` — не падай, верни `undefined`; иначе иди дальше».

### Пример

```ts
type User = {
  name: string;
  personalInfo: {
    age: number;
    address: { city: string };
    homeAddress?: { city: string };
  };
};

const user: User = { name: "Kate", personalInfo: { age: 25, address: { city: "Batumi" } } };

console.log(user.personalInfo.address.city);       // Batumi
console.log(user.personalInfo.homeAddress?.city);  // undefined — без ошибки
```

Без `?.` TypeScript не даст обратиться к опциональному `homeAddress`:

```ts
console.log(user.personalInfo.homeAddress.city);
// error TS18048: 'user.personalInfo.homeAddress' is possibly 'undefined'.
```

### Два разных знака вопроса

Не путайте:

| Где | Что значит |
|---|---|
| `homeAddress?: {...}` — в типе | свойство может отсутствовать |
| `homeAddress?.city` — при обращении | если значения нет, вернуть `undefined` вместо ошибки |

### Ставить ли ?. на каждом шаге

Лектор настаивает: при обращении к глубоко вложенному значению ставьте `?.` на каждом шаге цепочки, даже там, где свойство по типу обязательное. Аргумент — **стабильный код**: сегодня всё работает, а завтра кто-то изменит данные, и цепочка упадёт. Нестабильный код — это то, из-за чего в автотестах появляются flaky-тесты (нестабильные тесты — то проходят, то падают без изменений в коде).

Один из участников привёл пример из практики: backend вернул `null` там, где его никто не ждал. Позитивный сценарий проходит, а на продакшене код падает:

```ts
const apiUser = JSON.parse('{"name":"X","personalInfo":null}') as User;

apiUser.personalInfo.address.city;
// TypeError: Cannot read properties of null (reading 'address')

apiUser?.personalInfo?.address?.city; // undefined
```

**Уточнение — где правило лектора оправдано, а где это перестраховка.**

- **Оправдано** для данных извне: ответы API, JSON, данные со страницы. TypeScript проверяет типы только при компиляции, в рантайме (runtime — во время выполнения программы) он ничего не гарантирует. Если backend прислал `null`, аннотация типа от этого не спасёт.
- **Для собственных данных, описанных типами,** TypeScript сам потребует `?.` там, где значение может отсутствовать (ошибка TS18048 выше). А если кто-то попытается записать `undefined` в обязательное свойство, компилятор этого не пропустит. `?.` на обязательных свойствах ошибки не вызывает, но и ничего не защищает.
- **Про спор «`homeAddress?.city.a` или `homeAddress?.city?.a`».** Студент был прав в том, что в рантайме разницы нет: если `homeAddress` отсутствует, `?.` обрывает **всю оставшуюся цепочку**, и `.a` не выполняется. Второй `?.` нужен, только если `city` сам может отсутствовать.

```ts
type T = { homeAddress?: { city: string } };
const u: T = {};
console.log(u.homeAddress?.city.length); // undefined — без ошибки, .length не вычислялся
```

- **Важно не забыть:** `?.` прячет ошибку, но не решает проблему. Лектор тоже это отметил: в реальном коде после `?.` нужна проверка — что делать, если пришёл `undefined`. Для автотеста это особенно важно: тест, который молча получил `undefined` и прошёл, хуже упавшего.

## 17. Добавление и удаление свойств

### Базовый синтаксис

```ts
obj.новыйКлюч = значение;   // добавить (только если ключ объявлен в типе как опциональный)
delete obj.ключ;            // удалить (только опциональное свойство)
delete obj["ключ"];         // то же через квадратные скобки
delete obj[переменная];     // ключ из переменной
```

### Добавление

В JavaScript в объект можно добавить любое свойство. В TypeScript — только то, которое описано в типе как опциональное:

```ts
const p = { name: "Jim", age: 20 };
p.occupation = "QA";
// error TS2339: Property 'occupation' does not exist on type '{ name: string; age: number; }'.
```

С `occupation?: string` в типе то же присваивание проходит (пример в [разделе 15](#15-опциональные-свойства)).

### Удаление

```ts
const user: { name: string; age: number; occupation?: string } = { name: "Jim", age: 30, occupation: "QA" };

delete user.occupation;
console.log(user); // { name: 'Jim', age: 30 }
```

Удалить обязательное свойство нельзя — объект перестал бы соответствовать своему типу:

```ts
const p: { name: string; hobby: string } = { name: "Jim", hobby: "ski" };
delete p.hobby;
// error TS2790: The operand of a 'delete' operator must be optional.
```

- Несколько свойств удаляются по одному, каждое своим `delete`.
- Если удалить свойство, значение которого — объект, удалится весь вложенный объект.
- Удалить ключ во вложенном объекте: `delete user.personalInfo.homeAddress`.
- «Вернуть» удалённое свойство нельзя — можно только добавить заново с новым значением.

## 18. Копирование и сравнение объектов

Лектор затронул тему только в ответах на вопросы и сказал, что на курсе она не понадобится. Суть — всё как с массивами (массив тоже объект):

- **Поверхностная копия** (shallow copy — копируется только верхний уровень, вложенные объекты остаются общими): spread-оператор `{ ...obj }`.
- **Глубокая копия** (deep copy — копируются все уровни): `structuredClone(obj)`.

```ts
const orig = { name: "A", addr: { city: "T" } };

const shallow = { ...orig };
shallow.addr.city = "CHANGED";
console.log(orig.addr.city); // CHANGED — вложенный объект общий!

const deep = structuredClone(orig);
deep.addr.city = "DEEP";
console.log(orig.addr.city, deep.addr.city); // CHANGED DEEP
```

**Уточнение.** `structuredClone` **не умеет копировать функции**. Объект с методом вызовет ошибку:

```ts
const p = { name: "John", intro() { return "hi"; } };
structuredClone(p);
// DataCloneError: intro() { return "hi"; } could not be cloned.
```

Для объектов с методами используйте spread (методы скопируются как ссылки) или копируйте только данные. `structuredClone` доступен с Node.js 17.

**Уточнение — сравнение.** `===` сравнивает объекты по ссылке, а не по содержимому:

```ts
const a1 = { x: 1 }, a2 = { x: 1 };
console.log(a1 === a2);                                  // false — разные объекты
console.log(a1 === a1);                                  // true
console.log(JSON.stringify(a1) === JSON.stringify(a2));  // true — но зависит от порядка ключей
```

В автотестах объекты сравнивают специальными проверками: `toEqual` в Jest/Playwright, `deepStrictEqual` в Node.js. Они сравнивают содержимое, а не ссылки.

## 20. Шпаргалка и типичные ошибки

### Синтаксис

```ts
// Создание + тип
const user: { name: string; age: number; job?: string } = { name: "Jim", age: 30 };

// Чтение
user.name;
user["name"];
obj["key with spaces"];
obj.a.b.c;                     // вложенные

// Изменение / добавление / удаление
user.name = "Bob";
user.job = "QA";               // только если job?: в типе
delete user.job;               // только опциональное

// Вычисляемый ключ
const key = "greatSkier";
const o = { [key]: true };     // { greatSkier: true }

// Проверка наличия
"age" in user;
Object.hasOwn(user, "age");

// Методы
const p = {
  name: "Jim",
  full: function () { return this.name; },
  short() { return this.name; },          // рекомендуемая форма
  arrow: () => "no own this",             // this здесь НЕ объект
  withParam(greeting: string) { return `${greeting}, ${this.name}`; },
};
p.short();                     // вызов — со скобками

// Массивы из объекта
Object.keys(obj);              // ['a', 'b']
Object.values(obj);            // [1, 2]
Object.entries(obj);           // [['a', 1], ['b', 2]]

// Опциональная цепочка
user?.personalInfo?.homeAddress?.city;   // undefined вместо ошибки

// Копия
const shallow = { ...obj };
const deep = structuredClone(obj);       // без методов!
```

### Сводная таблица: где какой знак

| Знак | Где | Значение |
|---|---|---|
| `:` | в объекте | разделяет ключ и значение |
| `,` | в объекте | разделяет свойства |
| `:` | в типе | разделяет ключ и тип |
| `;` | в типе | разделяет свойства |
| `?` после ключа | в типе | свойство опционально |
| `?.` | при обращении | не падать на `null`/`undefined` |
| `[x]` | ключ в объекте | ключ из переменной `x` |
| `["x y"]` | при обращении | ключ-строка (например, с пробелом) |

### Обычная функция vs стрелочная как метод

| | `метод() { }` / `function` | `метод: () => ...` |
|---|---|---|
| Свой `this` | есть — объект слева от точки | нет — берётся у внешнего кода |
| `this.name` внутри | значение свойства объекта | ошибка TS / `undefined` / `TypeError` |
| Когда использовать | методы объекта | колбэки **внутри** методов |

### Типичные ошибки

1. **Вызов метода без скобок.** `p.greet` вместо `p.greet()` — получите функцию, а не результат.
2. **Забыли `this`.** `return name` внутри метода вместо `this.name` — возьмётся внешняя переменная (или ошибка), а не свойство объекта.
3. **Имя объекта вместо `this`.** `person.name` внутри метода ломается при копировании объекта или передаче метода другому объекту.
4. **Стрелочная функция как метод с `this`.** У стрелочной функции нет своего `this`.
5. **Метод, вызванный без объекта.** `const f = obj.method; f();` — `this` потерян, `TypeError`.
6. **`[key]` вместо `"key"` (и наоборот).** Скобки без кавычек — ключ из переменной; кавычки — буквальное имя.
7. **Запятые вместо точек с запятой в типе** (и наоборот в объекте).
8. **Добавление свойства, которого нет в типе.** TS2339 — объявите его как опциональное.
9. **`delete` обязательного свойства.** TS2790.
10. **`obj[key]` в цикле по `Object.keys`.** TS7053 — используйте `Object.entries`.
11. **Обращение к вложенному свойству опционального объекта без `?.`.** TS18048 при компиляции, `TypeError` в рантайме.
12. **`?.` вместо обработки ошибки.** `undefined` без проверки — тихий баг; в тесте — ложное прохождение.
13. **`structuredClone` объекта с методами.** `DataCloneError`.
14. **Сравнение объектов через `===`.** Сравниваются ссылки, а не содержимое.
15. **Одинаковые имена у переменных и ключей.** Путаница с затенением — называйте по-разному.
