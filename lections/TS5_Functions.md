## 1. Что такое функция и зачем она нужна

**Функция** — кусок кода, написанный отдельно от остального и решающий одну конкретную задачу. Функция — это ещё и тип данных: `typeof` от функции возвращает `"function"`.

Задача, из которой всё выросло. Нужно напечатать разделитель и результат вычисления — и так несколько раз:

```ts
console.log("--------------------");
console.log(`5 + 10 = ${5 + 10}`);
console.log("--------------------");
console.log(`5 - 10 = ${5 - 10}`);
console.log("--------------------");
console.log(`5 * 10 = ${5 * 10}`);
```

Один и тот же кусок повторяется. Добавится деление и остаток — повторится ещё дважды. Отсюда и ошибки: где-то забыли `\n`, где-то опечатались в слове, и всё это нужно править в каждом экземпляре.

Функции решают три задачи: переиспользовать код вместо копирования, объединить связанную логику в одном месте и сделать код читаемым.

## 2. Объявление и вызов функции

### Базовый синтаксис

```ts
function ИмяФункции(): ТипВозвращаемогоЗначения {
    // тело функции
    return результат;
}

ИмяФункции();   // вызов
```

Разбор по частям:

- `function` — зарезервированное слово;
- имя функции — должно быть понятным, объяснять, что функция делает;
- **круглые скобки обязательны всегда**, даже если параметров нет;
- после двоеточия — тип данных, который функция **возвращает** (не тип самой функции);
- фигурные скобки — тело функции, как в циклах и `if`;
- `return` — что функция отдаёт наружу.

### Пример

```ts
function Greetings(): string {
    return "Hello!";
}

console.log(Greetings());   // Hello!
```

Тип `string` стоит потому, что функция возвращает строку.

### Вызов обязателен

Объявление функции само по себе ничего не выполняет. Код увидит функцию, но её тело не сработает, пока функцию не вызовут — по имени, **со скобками**.

Скобки — принципиальны. Без них вы обращаетесь к самой функции, со скобками — просите её выполнить:

```ts
console.log(typeof Greetings);     // "function"  — что это такое
console.log(typeof Greetings());   // "string"    — что она вернула
```

Этот вопрос задавали на лекции: «почему без скобок выводится `function`?» Потому что без скобок вы не просили код заходить внутрь функции — вы спросили, что такое `Greetings`. Ответ: функция.


### Пример из начала: та же задача через функцию

```ts
function Print(a: number, b: number, sign: string): void {
    console.log("--------------------");
    console.log(`${a} ${sign} ${b}`);
}

Print(5, 10, "+");
Print(5, 10, "-");
Print(5, 10, "*");
```

Повторяющийся код написан один раз. Про `void` — следующий раздел.


**Уточнение (именование функций).** Лектор сказал: имя функции начинается с большой буквы, а при нескольких словах каждое слово с большой (`PrintResult`). Это соглашение конкретно этого курса, и внутри курса ему нужно следовать. Но в большинстве реальных проектов на JS/TS принято иначе: **функции именуются с маленькой буквы** (`printResult`, `getUserName`), а запись с большой буквы (PascalCase) зарезервирована за классами и React-компонентами. Когда будете читать чужой код или код из вакансий — вы увидите именно camelCase, и это не ошибка автора.

## 3. `return` — возвращает и останавливает

`return` делает две вещи одновременно: отдаёт значение наружу и **немедленно завершает функцию**. Всё, что написано после него, не выполнится:

```ts
function Test(): string {
    return "первое";
    return "второе";   // недостижимый код
}

console.log(Test());   // "первое"
```

**Ловушка с переносом строки.** Значение должно стоять на той же строке, что и `return`:

```ts
function Broken() {
    return
        "значение на следующей строке";
}

console.log(Broken());   // undefined
```

**Уточнение.** Причина — механизм автоматической вставки точки с запятой в JavaScript (ASI): интерпретатор видит `return` в конце строки и сам дописывает после него точку с запятой. Получается `return;`, а строка ниже становится недостижимой. Это одно из немногих мест, где перенос строки меняет смысл кода.

## 4. Тип `void` — функция ничего не возвращает

Функция `Print` из раздела 2 ничего не возвращает — она только печатает. Такая функция называется void-функцией.

### Базовый синтаксис

```ts
function ИмяФункции(): void {
    // тело без return значения
}
```

### Пример

```ts
function Print(a: number, b: number): void {
    console.log(`${a} + ${b} = ${a + b}`);
}

Print(5, 10);                     // 5 + 10 = 15
console.log(typeof Print(5, 10)); // "undefined"
```

Тип результата void-функции — `undefined`. Само значение вам не нужно, поэтому и писать `return` незачем.

Без указания `void` код тоже отработает — TypeScript выведет тип сам. Но на этом курсе тип пишется всегда, и вот почему: на реальной работе код проходит дополнительные проверки (линтеры, настройки компилятора), и код без указанных типов просто не пропустят дальше — ни в продакшен, ни на сервер. Учиться сразу правильно дешевле, чем переучиваться.

**Уточнение (важно).** На лекции прозвучало: «`void` — это когда слова `return` внутри функции не существует; если поставить `return` в void-функции, будет ошибка». Это не так. Пустой `return;` в void-функции разрешён и часто используется для досрочного выхода:

```ts
function Check(value: number): void {
    if (value < 0) {
        return;          // компилируется без ошибок
    }
    console.log(value);
}
```

Ошибка возникает только если возвращать **значение**:

```ts
function Print(): void {
    return 5;   // ошибка: Type 'number' is not assignable to type 'void'
}
```

Правильная формулировка: void-функция не возвращает **значения**, но выйти из неё через `return;` можно.

## 5. Тип `never` — функция не завершается нормально

`never` похож на `void`, но означает другое. `void` — «функция отработала и ничего не вернула». `never` — «функция никогда не доходит до конца»: она обрывает выполнение.

### Базовый синтаксис

```ts
function ИмяФункции(): never {
    throw new Error("текст ошибки");
}
```

### Пример

```ts
function ThrowError(): never {
    throw new Error("Something went wrong");
}
```

Как только сработал `throw`, всё останавливается — до конца функции выполнение не доходит, возвращать нечего. Поэтому тип не `void`, а `never`: void-функция возвращает `undefined`, а never-функция не возвращает вообще ничего.

Где ещё встречается `never`, по словам лектора:

- вместо `throw` может стоять запись в лог с последующей остановкой — суть та же;
- в некоторых настройках TypeScript `never` подставляется там, где иначе получился бы `any`.

`never` используется редко. Лектор прямо сказал, что на курсе он, скорее всего, не понадобится ни разу — знать нужно просто чтобы узнавать его в чужом коде.

## 6. Параметры функции

Значения, которые функция получает снаружи при вызове.

### Базовый синтаксис

```ts
function ИмяФункции(параметр1: Тип, параметр2: Тип): ТипРезультата {
    // тело
}

ИмяФункции(значение1, значение2);
```

Параметры разделяются запятыми, у каждого свой тип. Именуются в camelCase — с маленькой буквы, каждое следующее слово с большой (`numberOne`).

### Пример

```ts
function Sum(numberOne: number, numberTwo: number): number {
    return numberOne + numberTwo;
}

console.log(Sum(5, 10));   // 15
console.log(Sum(1, 2));    // 3
```

Параметров может быть сколько угодно. Но если их набралось десять — скорее всего, функция делает слишком много; лектор обещал вернуться к тому, как этого избегать.

По умолчанию нужно передавать **ровно столько** значений, сколько объявлено параметров, иначе будет ошибка. Исключения — следующие два раздела.

**Уточнение (параметры и аргументы).** На лекции этот вопрос задали, группа запуталась, и лектор предложил называть как угодно. Разница есть, и она простая:

- **параметр** (parameter) — имя в объявлении функции: `numberOne`, `numberTwo`;
- **аргумент** (argument) — конкретное значение при вызове: `5`, `10`.

Проверить легко: наведите курсор на `numberOne` в объявлении — VS Code покажет «parameter». Различать стоит по практической причине, которую на лекции назвали правильно: условия задач на Codewars и LeetCode написаны по-английски, и там эти слова используются строго. «The function takes two parameters» и «pass the array as an argument» описывают разные места кода.

## 7. Параметр по умолчанию

Если аргумент не передали, параметр примет заранее заданное значение.

### Базовый синтаксис

```ts
function ИмяФункции(обязательный: Тип, сЗначением: Тип = значение): ТипРезультата {
    // тело
}
```

### Пример

```ts
function Sum(a: number, b: number = 10): number {
    return a + b;
}

console.log(Sum(5, 2));   // 7   — взяли переданное значение
console.log(Sum(5));      // 15  — взяли значение по умолчанию
```

Проверять такой параметр внутри функции не нужно: значение у него есть всегда.

## 8. Опциональный параметр

Второй вариант: параметр может быть передан, а может и нет, и никакого значения по умолчанию у него нет.

### Базовый синтаксис

```ts
function ИмяФункции(обязательный: Тип, опциональный?: Тип): ТипРезультата {
    if (опциональный !== undefined) {
        // ветка, когда значение передали
    }
    // ветка, когда не передали
}
```

Знак вопроса после имени параметра означает «необязательный».

### Пример

```ts
function Sum(a: number, b?: number): number {
    if (b !== undefined) {
        return a + b;
    }
    return a + 10;
}

console.log(Sum(5, 2));   // 7
console.log(Sum(5));      // 15
```

**Проверка обязательна.** Если аргумент не передали, параметр равен `undefined`, и использовать его напрямую нельзя:

```ts
function Sum(a: number, b?: number): number {
    return a + b;   // ошибка: 'b' is possibly 'undefined'
}
```

Без проверки в чистом JavaScript ошибки компиляции не будет, но результат окажется `NaN` — `5 + undefined` не число. TypeScript ловит это заранее.

**Нельзя совмещать `?` и значение по умолчанию.** В JavaScript такая запись встречалась, в TypeScript она запрещена:

```ts
function Sum(a: number, b?: number = 10): number {   // ошибка TS1015:
    return a + b;                                     // Parameter cannot have
}                                                     // question mark and initializer
```

Выбирайте одно: либо `b: number = 10` (значение по умолчанию, проверка не нужна), либо `b?: number` (может отсутствовать, проверка обязательна).

## 9. Область видимости переменных

Правило то же, что в циклах и `if`:

- **снаружи → внутрь — видно.** Переменные, объявленные снаружи функции, доступны внутри неё;
- **изнутри → наружу — не видно.** Переменные, объявленные внутри фигурных скобок функции, существуют **только внутри неё**.

```ts
const c: number = 100;

function Sum(a: number, b: number): number {
    const d: number = 5;
    return a + b + c + d;   // c видна внутри функции
}

console.log(Sum(1, 3));   // 109
// console.log(d);        // ошибка: d не существует снаружи
```

## 10. Функция внутри функции

Функцию можно объявить внутри другой функции. Внутренняя функция видна только внутри внешней.

```ts
function Outer(): string {
    function Inner(): number {
        return 5;
    }
    return "Hello" + Inner();
}

console.log(Outer());   // "Hello5"
// console.log(Inner()); // ReferenceError: Inner is not defined
```

Разбор: вызвали `Outer` → она начала собирать строку → дошла до `Inner()` → нашла внутреннюю функцию → получила `5` → подставила в результат.

**ДЗ от лектора:** попробовать вызвать `Inner()` снаружи и посмотреть, что получится.

На лекции всплыл случай, когда внутренняя функция обращается к переменной внешней и ведёт себя неочевидно. Это **замыкания** (closures) — отдельная тема, лектор отложил её на review, отметив, что для автоматизаторов она нужна реже, чем для разработчиков.

## 11. Рекурсивная функция

**Рекурсивная функция** — функция, которая вызывает саму себя.

### Пример: возведение в квадрат по цепочке

```ts
function Square(num: number): number | undefined {
    if (num > 1000) {
        return;                    // условие остановки
    }
    console.log(num);
    const square: number = num * num;
    return Square(square);         // функция вызывает саму себя
}

Square(2);
```

Вывод:

```
2
4
16
256
```

Пошагово: пришла `2` → напечатали → возвели в квадрат, получили `4` → передали `4` в ту же функцию → напечатали → `16` → `256` → `65536`, что больше 1000, значит сработал `return` и цепочка оборвалась.

### Условие остановки обязательно

Без него функция вызывает себя бесконечно:

```ts
function Endless(num: number): number {
    return Endless(num * num);   // остановки нет
}
```

Результат — `RangeError: Maximum call stack size exceeded`, переполнение стека вызовов: память, отведённая под вложенные вызовы функций, заканчивается.

Механизм остановки зависит от задачи: сравнение с числом, счётчик, любое другое условие. Важно, что он должен быть — так же, как условие выхода в цикле.

### `return;` как аналог `break`

Пустой `return;` без значения — способ выйти из функции досрочно. Это прямой аналог `break` в цикле и `switch` (сам `break` внутри функции не работает).

Возвращаемое при этом значение — `undefined`, и оно никому не нужно. Не дописывайте туда `return null;` или `return 0;` только ради того, чтобы что-то вернуть: это мусор, который в будущем кого-то запутает, и его придётся долго искать. Правило то же, что и с переменными: **делаем только то, что действительно нужно**.

**Уточнение (ответ на вопрос, который на лекции остался открытым).** Лектор не смог объяснить, почему подсказка редактора показывает для такой функции тип `void`, хотя та возвращает то число, то `undefined`. Объяснение: при выводе типа рекурсивной функции TypeScript опирается только на **нерекурсивные** `return`. Здесь такой один — пустой `return;`, то есть `void`. Строка `return Square(square)` для вывода типа не используется, иначе вывод зациклился бы.

Поэтому тип надо указать руками, и вариантов два:

```ts
// вариант 1: функция действительно возвращает число либо ничего
function Square(num: number): number | undefined { ... }

// вариант 2: функция только печатает, результат не нужен
function Square(num: number): void {
    if (num > 1000) {
        return;
    }
    console.log(num);
    Square(num * num);     // без return
}
```

Если написать `: number` и оставить пустой `return;`, будет ошибка `Type 'undefined' is not assignable to type 'number'` — ровно её на лекции и получили.

## 12. Три формы записи функции

Одну и ту же функцию можно записать тремя способами.

### Function declaration — объявление функции

```ts
function Sum(a: number, b: number): number {
    return a + b;
}

console.log(Sum(1, 2));   // 3
```

У функции есть имя, по имени её и вызывают. Точка с запятой после закрывающей фигурной скобки **не ставится**.

### Function expression — функциональное выражение

Функцию присваивают переменной, и дальше работают с переменной.

```ts
const sum = function (a: number, b: number): number {
    return a + b;
};

console.log(sum(1, 2));   // 3
```

Обратите внимание на **точку с запятой в конце** — она обязательна. Принадлежит она не функции, а объявлению переменной: по сути это `const sum = <что-то>;`, как и любая другая переменная.

Имя функции здесь не нужно: вызываем-то мы переменную, а не функцию по имени. Функция без имени называется **анонимной**.

Тип у переменной не указывают: её тип — «функция», а не то, что функция возвращает:

```ts
console.log(typeof sum);        // "function"
console.log(typeof sum(1, 2));  // "number"
```

### Arrow function — стрелочная функция

Разновидность function expression, где убрано и имя, и само слово `function`.

```ts
const sum = (a: number, b: number): number => a + b;

console.log(sum(1, 2));   // 3
```

Подробнее — в разделе 14.

## 13. Подъём функции (hoisting)

**Function hoisting** (подъём функции) — механизм, при котором объявленную функцию можно вызвать **до** того места, где она написана.

```ts
console.log(Sum(1, 2));   // 3 — работает, хотя функция объявлена ниже

function Sum(a: number, b: number): number {
    return a + b;
}
```

Как это устроено: перед выполнением кода движок бегло сканирует файл, находит все объявления функций и «поднимает» их в начало. Только после этого начинается обычное выполнение сверху вниз.

Зачем: удобно писать логику сверху, а сами функции складывать внизу файла. Это распространённый стиль.

**Подъём работает только для function declaration.** Для function expression и стрелочных функций — нет:

```ts
console.log(sum(1, 2));   // ошибка: Block-scoped variable 'sum' used before its declaration

const sum = function (a: number, b: number): number {
    return a + b;
};
```

Причина: здесь нет отдельно существующей функции. Есть переменная, которой присваивается функция, а обратиться к переменной до её объявления нельзя — ровно так же, как нельзя написать `console.log(a)` до `let a = 5`.

## 14. Стрелочная функция

Самая часто используемая форма. По оценке лектора — 80–90% случаев в реальном коде, а на практической части курса она будет встречаться повсеместно.

### Базовый синтаксис

```ts
// полная форма — с телом и return
const имя = (параметры): ТипРезультата => {
    return результат;
};

// краткая форма — одно выражение, без фигурных скобок и без return
const имя = (параметры): ТипРезультата => выражение;
```

Стрелка `=>` заменяет слово `function` и сообщает коду, что перед ним функция. Без стрелки запись не работает — код не понимает, что это функция.

Круглые скобки обязательны всегда, даже если параметров нет: `const f = (): void => { ... };`

### Пример: обе формы

```ts
const sumLong = (a: number, b: number): number => {
    const result: number = a + b;
    return result;
};

const sumShort = (a: number, b: number): number => a + b;

console.log(sumLong(1, 2));    // 3
console.log(sumShort(1, 2));   // 3
```

Краткая форма — то, ради чего стрелочные функции так любят. Когда действие умещается в одну строку, фигурные скобки и `return` — лишний шум. На десяти строках кода это незаметно, на тысячах — заметно очень.

Краткая форма подходит только для одного выражения. Как только внутри появляются переменные, условия или циклы — нужна полная форма с фигурными скобками.

### Как из обычной функции получается стрелочная

Логика вывода, которую лектор разобрал по шагам:

```ts
// 1. обычная функция с именем
function Sum(a: number, b: number): number { return a + b; }

// 2. присвоили переменной — имя функции больше не нужно, вызываем-то переменную
const sum = function Sum(a: number, b: number): number { return a + b; };

// 3. убрали имя — анонимная функция
const sum = function (a: number, b: number): number { return a + b; };

// 4. убрали слово function, поставили стрелку
const sum = (a: number, b: number): number => { return a + b; };

// 5. одно выражение — убрали скобки и return
const sum = (a: number, b: number): number => a + b;
```

**Уточнение (главное отличие стрелочных функций).** На вопрос «какие у стрелочных функций особенности?» на лекции прозвучало: нет имени, нет подъёма, а в остальном то же самое. Есть ещё одно, и оно важнее перечисленных: у стрелочной функции **нет собственного `this`** — она берёт `this` из окружающего кода. Это и делает её удобной внутри методов и колбэков. Тему `this` на курсе ещё не проходили, но когда дойдёте — держите этот факт в голове, потому что именно из-за него стрелочные и обычные функции не всегда взаимозаменяемы.

## 15. Что когда использовать

Рекомендации лектора:

- **Function declaration** — когда функции собраны в отдельный файл-библиотеку (utility-файл): там их 15–20, и они вызываются из других файлов по именам. Подъём здесь тоже кстати.
- **Стрелочная функция** — во всех остальных случаях, особенно для коротких действий и колбэков. Основной рабочий вариант.
- **Function expression с именем** (`const sum = function Sum() {...}`) — почти не встречается. Лектор показал её только как промежуточный шаг в выводе стрелочной формы.

## 16. Методы и функции

Вопрос, который задали в начале лекции: чем метод отличается от функции?

**Метод — это функция, которая чему-то принадлежит.**

Всё, что вы до сих пор писали, — просто функции, они не принадлежат ничему. А `arr.push()`, `str.toUpperCase()`, `arr.split()` — методы: это функции, написанные внутри самого TypeScript и привязанные к массиву, строке, числу.

Никаких дополнительных возможностей у метода нет. Разница только в принадлежности — и в том, что вызывается он через точку от значения.

Как именно функция «принадлежит» чему-то, лектор обещал разобрать через занятие-два. Пока достаточно понимать: метод строки принадлежит строке, метод массива — массиву, и внутри это обычная функция, которая принимает аргументы и что-то возвращает. Как она устроена внутри — знать не нужно; важно, что она делает и что возвращает.

## 17. `map`

Первый из трёх главных методов массива. `map` **сам** проходит по всему массиву и создаёт **новый** массив той же длины.

### Базовый синтаксис

```ts
массив.map((элемент, индекс, исходныйМассив) => выражение);
```

Второй и третий параметры опциональные — их указывают только если они нужны.

Функция, которую вы передаёте внутрь `map`, называется **callback-функцией** (функция обратного вызова): вы передаёте её как аргумент, а `map` вызывает её сам — столько раз, сколько элементов в массиве.

### Пример: умножить каждый элемент на два

Как это делалось раньше, циклом:

```ts
const arr: number[] = [1, 2, 3, 4, 5];
const newArr: number[] = [];

for (let i: number = 0; i < arr.length; i++) {
    newArr.push(arr[i] * 2);
}

console.log(newArr);   // [ 2, 4, 6, 8, 10 ]
```

То же самое через `map` — с отдельной именованной функцией:

```ts
function MultiplyByTwo(element: number): number {
    return element * 2;
}

const newArr = arr.map(MultiplyByTwo);
console.log(newArr);   // [ 2, 4, 6, 8, 10 ]
```

И то, как это пишут на практике — со стрелочной функцией:

```ts
const newArr = arr.map((el) => el * 2);
console.log(newArr);   // [ 2, 4, 6, 8, 10 ]
console.log(arr);      // [ 1, 2, 3, 4, 5 ]  — исходный массив не изменился
```

Цикл и `push` `map` делает за вас. Имя параметра (`el`, `element`, `item`, `number`) — любое, это просто название.

### Пример: градусы Цельсия в Фаренгейты

```ts
const celsius: number[] = [0, 10, 20, 30];
const fahrenheit: number[] = celsius.map((c) => c * 9 / 5 + 32);

console.log(fahrenheit);   // [ 32, 50, 68, 86 ]
```

На первой итерации `c` равно `0`, на второй `10`, на третьей `20`, на четвёртой `30`.

### Второй параметр — индекс

Нужен, когда действие зависит от позиции элемента.

```ts
const result = [1, 2, 3].map((el, index) => index !== 2 ? el * 2 : el);
console.log(result);   // [ 2, 4, 3 ]  — третий элемент не удвоился
```

Третий параметр — сам исходный массив. Нужен крайне редко: только если внутри `map` вы меняете исходный массив (лектор назвал это очень плохой практикой) и вам нужно видеть, чем он был.

### Когда `map` не подходит

`map` заменяет ровно один вид цикла — обход всего массива от начала до конца:

```ts
for (let i: number = 0; i < arr.length; i++) { ... }
```

Если условие другое — пройти половину массива, идти с шагом, начать не с нуля — `map` не подойдёт, нужен обычный цикл. Условия и `if` внутри `map` при этом использовать можно.

**Уточнение.** `map` всегда возвращает массив **той же длины**, что исходный. Если из каждого элемента нужно что-то получить — это `map`. Если нужно отобрать часть элементов — это `filter` (раздел 19). Использовать `map` для отбора технически можно, но тогда придётся отдельно чистить результат от ненужных элементов.

## 18. `forEach`

### Базовый синтаксис

```ts
массив.forEach((элемент, индекс, исходныйМассив) => { /* действие */ });
```

Работает как `map` — проходит по каждому элементу и выполняет callback-функцию. Отличие одно: **ничего не возвращает**.

```ts
const result = [1, 2, 3].forEach((el) => el * 2);
console.log(result);   // undefined
```

Название по аналогии с `for`: для массивов есть `forEach`.

**Уточнение.** Практическое следствие: раз `forEach` возвращает `undefined`, его результат нельзя использовать дальше и нельзя продолжить цепочкой (раздел 22). `forEach` берут, когда нужно что-то сделать с каждым элементом, а результат не нужен — например, напечатать. Если результат нужен — `map`.

## 19. `filter`

Отбирает из массива элементы, подходящие под условие, и возвращает **новый массив**.

### Базовый синтаксис

```ts
массив.filter((элемент, индекс, исходныйМассив) => условие);
```

Callback должен вернуть `true` или `false`: `true` — элемент попадает в результат, `false` — не попадает.

### Пример: слова длиннее шести букв

```ts
const words: string[] = ["hello", "autumn", "fun", "beautiful", "wonderful"];
const longWords: string[] = words.filter((word) => word.length > 6);

console.log(longWords);          // [ 'beautiful', 'wonderful' ]
console.log(words.length);       // 5
console.log(longWords.length);   // 2
```

### Пример: чётные числа

```ts
const numbers: number[] = [1, 2, 3, 4];
const even: number[] = numbers.filter((n) => n % 2 === 0);

console.log(even);   // [ 2, 4 ]
```

Остаток от деления на 2 равен нулю — число чётное.

### `map` или `filter`

| | Что делает | Длина результата |
|---|---|---|
| `map` | изменяет каждый элемент | **всегда** равна исходной |
| `filter` | отбирает часть элементов | может быть любой, от 0 до исходной |

## 20. `includes`

Проверяет, есть ли значение в массиве. Возвращает `true` или `false`.

### Базовый синтаксис

```ts
массив.includes(искомоеЗначение, начальныйИндекс);
```

Второй параметр — с какого индекса начинать поиск, необязательный.

### Пример

```ts
const animals: string[] = ["cat", "dog", "bird"];

console.log(animals.includes("dog"));    // true
console.log(animals.includes("fish"));   // false
```

С указанием начального индекса:

```ts
const abc: string[] = ["A", "B", "C"];

console.log(abc.includes("B", 1));   // true  — ищем с индекса 1, "B" там и стоит
console.log(abc.includes("B", 2));   // false — ищем с индекса 2, "B" уже позади
```

## 21. `reduce`

Самый сложный из разобранных методов. Сворачивает весь массив в **одно значение** — число, строку, что угодно.

### Базовый синтаксис

```ts
массив.reduce((аккумулятор, текущийЭлемент) => выражение, начальноеЗначение);
```

`reduce` — единственный из разобранных методов, который принимает **два** аргумента: callback-функцию и начальное значение (второй необязателен, но см. ниже).

Внутри callback-функции два параметра:

- **аккумулятор** (часто `acc`) — копит результат между итерациями;
- **текущий элемент** (`cur`, `current`, `item`) — элемент, до которого дошли сейчас.

### Пример: сумма элементов массива

```ts
const numbers: number[] = [1, 2, 3, 4];
const sum: number = numbers.reduce((acc, cur) => acc + cur, 0);

console.log(sum);   // 10
```

Пошагово, с начальным значением `0`:

| Итерация | `acc` | `cur` | Результат → в `acc` |
|---|---|---|---|
| 1 | 0 | 1 | 1 |
| 2 | 1 | 2 | 3 |
| 3 | 3 | 3 | 6 |
| 4 | 6 | 4 | 10 |

Когда массив закончился, `reduce` отдаёт значение аккумулятора — `10`.

### Что меняет начальное значение

Если начальное значение **не указано**, всё сдвигается: аккумулятор стартует с первого элемента массива, а текущий элемент — со второго.

```ts
console.log(numbers.reduce((acc, cur) => acc + cur));        // 10 — acc=1, cur=2 на первом шаге
console.log(numbers.reduce((acc, cur) => acc + cur, 0));     // 10 — acc=0, cur=1 на первом шаге
console.log(numbers.reduce((acc, cur) => acc + cur, 100));   // 110
```

Начальное значение можно вынести в переменную, если так читается лучше:

```ts
const initialValue: number = 100;
const sum: number = numbers.reduce((acc, cur) => acc + cur, initialValue);
```

### Почему начальное значение стоит указывать всегда

На лекции об этом был спор, и лектор прав: **аккумулятор без начального значения равен не нулю, а первому элементу массива**. Для сложения разница незаметна, но:

- при умножении начальное значение `0` обнулит вообще всё — нужно `1`;
- если первый элемент окажется не числом (`undefined`, строка), расчёт поедет с самого начала;
- с явным начальным значением вы сразу задаёте тип аккумулятора.

Поэтому `reduce((acc, cur) => acc + cur, 0)` предпочтительнее, чем `reduce((acc, cur) => acc + cur)`, даже когда результат совпадает.

**Уточнение (в лекции не прозвучало).** У `reduce` без начального значения есть ещё одна проблема: на пустом массиве он выбрасывает ошибку.

```ts
console.log([].reduce((a, b) => a + b));      // TypeError: Reduce of empty array with no initial value
console.log([].reduce((a, b) => a + b, 0));   // 0
```

Для QA это знакомый класс багов: код отлично работает на тестовых данных и падает, когда API вернул пустой список. Ещё один аргумент за то, чтобы начальное значение писать всегда.

### Когда `reduce` не подходит

Когда из массива в принципе не получается сделать одно значение. Обычно `reduce` применяют для математики, подсчёта длины, склейки текстов.

Лектор честно предупредил, что `reduce` редко понятен с первого раза, и предложил вернуться к нему на review.

## 22. Цепочка вызовов

Методы можно вызывать подряд через точку:

```ts
const words: string[] = ["hello", "autumn", "fun", "beautiful", "wonderful"];
console.log(words.filter((word) => word.length > 6).length);   // 2
```

Это называется **цепочка вызовов** (chaining). Ключевой момент, который на лекции подчеркнули: второй метод применяется **не к исходному массиву, а к результату первого**. В примере `.length` берётся от отфильтрованного массива, а не от `words`.

Именно поэтому `forEach` в цепочку не встроить — он возвращает `undefined`, и продолжать нечего.

## 24. Шпаргалка и типичные ошибки

### Синтаксис на одной странице

```ts
// объявление функции
function Sum(a: number, b: number): number {
    return a + b;
}
Sum(1, 2);

// ничего не возвращает
function Print(text: string): void {
    console.log(text);
}

// не завершается нормально
function Fail(): never {
    throw new Error("boom");
}

// параметр по умолчанию / опциональный
function A(a: number, b: number = 10): number { return a + b; }
function B(a: number, b?: number): number {
    return b !== undefined ? a + b : a;
}

// function expression (точка с запятой обязательна)
const sum = function (a: number, b: number): number { return a + b; };

// стрелочная функция
const sumShort = (a: number, b: number): number => a + b;
const sumLong = (a: number, b: number): number => {
    return a + b;
};

// методы массива
arr.map((el) => el * 2);            // новый массив той же длины
arr.forEach((el) => console.log(el)); // ничего не возвращает
arr.filter((el) => el > 5);          // новый массив, длина другая
arr.includes("dog", 1);              // true / false
arr.reduce((acc, cur) => acc + cur, 0); // одно значение
```

### Три формы записи

| Форма | Имя функции | Подъём | Точка с запятой в конце |
|---|---|---|---|
| `function Sum() {}` | есть | **да** | нет |
| `const sum = function () {};` | нет (анонимная) | нет | **да** |
| `const sum = () => {};` | нет (анонимная) | нет | **да** |

### Методы массива

| Метод | Возвращает | Длина результата |
|---|---|---|
| `map` | новый массив | равна исходной |
| `forEach` | `undefined` | — |
| `filter` | новый массив | от 0 до исходной |
| `includes` | `true` / `false` | — |
| `reduce` | одно значение | — |

### Частые ошибки

1. **Забыть скобки при вызове.** `Sum` — это сама функция, `Sum()` — её вызов. Без скобок получите `[Function: Sum]`, а не результат.
2. **Написать значение на строке после `return`** — функция вернёт `undefined`.
3. **Использовать опциональный параметр без проверки** — компилятор не пропустит, а в JavaScript получится `NaN`.
4. **Совместить `?` и значение по умолчанию** — ошибка TS1015, так нельзя.
5. **Вызвать function expression или стрелочную функцию до объявления** — подъём на них не действует.
6. **Поставить точку с запятой после `function Sum() {}`** — она там лишняя, линтер укажет на неё.
7. **Забыть точку с запятой после function expression** — а вот она обязательна, это конец объявления переменной.
8. **Сделать рекурсию без условия остановки** — переполнение стека.
9. **Возвращать `null` или `0` там, где значение не нужно** — мусор, который потом кого-то запутает. Нужен только выход — пишите `return;`.
10. **Вызвать `reduce` без начального значения** — на пустом массиве ошибка, при умножении и нечисловых данных неверный результат.
11. **Ждать от `forEach` результата** — он всегда `undefined`, в цепочку его не поставить.
