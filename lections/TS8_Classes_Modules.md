# Часть 1. Классы

## 1. Зачем нужны классы

На прошлых занятиях объекты создавались вручную:

```ts
const person1 = { firstName: "John", age: 30 };
const person2 = { firstName: "Susan", age: 25 };
const person3 = { firstName: "Jennifer", age: 26 };
```

Ключи у всех одинаковые, различаются только значения. Интерфейс описывает форму такого объекта, но каждый объект всё равно приходится выписывать руками. Функция, возвращающая объект, помогает частично, но это тоже ручная работа.

Нужен способ, при котором объект со всеми свойствами создаётся автоматически. Это и есть классы.

**Класс — это шаблон, по которому создаются объекты.** Сам класс объектом не является: он описывает, какие поля и методы будут у объектов, созданных из него.

---

## 2. Объявление класса и конструктор

### Базовый синтаксис

```ts
class ИмяКласса {
    constructor(параметры) {
        // тело конструктора
    }
}
```

- `class` — зарезервированное слово;
- имя класса пишется с большой буквы (PascalCase), как и имена типов;
- `constructor` — зарезервированное слово;
- круглые скобки конструктора принимают аргументы, как у обычной функции;
- фигурные скобки — тело класса.

**Конструктор** — специальная функция внутри класса. Она выделяет память, создаёт экземпляр класса и выполняется автоматически при каждом создании объекта. Отдельно вызвать конструктор нельзя — он срабатывает сам, когда вы пишете `new`.

Конструктор есть в каждом классе. Если параметров нет, его можно не писать — TypeScript подставит пустой конструктор сам:

```ts
class Empty {
    greet(): string { return "hi"; }
}
// эквивалентно классу с constructor() {}
```

## 3. Поля класса и `this`

**Поле** (field) — то, что в обычном объекте было ключом. Поля объявляются внутри класса, до конструктора, с указанием типа.

**`this`** указывает на тот конкретный объект, который создаётся прямо сейчас. Без `this` класс не знал бы, какому из будущих объектов присваивать значение.

### Пример

```ts
class Person {
    firstName: string;     // поля класса
    age: number;

    constructor(firstName: string, age: number) {   // аргументы извне
        this.firstName = firstName;   // this.firstName — поле, firstName — аргумент
        this.age = age;
    }
}
```

Разбор строки `this.firstName = firstName`:

- слева `this.firstName` — **поле класса**, то, что станет свойством будущего объекта;
- справа `firstName` — **аргумент конструктора**, значение, пришедшее извне.

Это два разных имени одной строки, и путаница здесь обычная. Правило, которое лектор просил запомнить: **всё со словом `this` — это поле; всё в круглых скобках конструктора — это то, что пришло извне.**

### Область видимости

- аргументы конструктора видны **только внутри конструктора** — после его работы они исчезают;
- поля класса видны **внутри всего класса**, включая конструктор и методы.

Именно поэтому поле и аргумент можно называть одинаково: они живут в разных местах и не конфликтуют.

На лекции спросили, можно ли назвать их по-разному, чтобы не путаться. Технически можно, на практике так не делают — на работе такой код вызовет вопросы. Кроме того, существует короткая запись (раздел 14), после которой проблема исчезает сама.

## 4. Создание объекта: `new`

### Базовый синтаксис

```ts
const имяОбъекта: ИмяКласса = new ИмяКласса(аргументы);
```

Слово `new` запускает конструктор и создаёт **экземпляр класса** — объект.

### Пример

```ts
const alice: Person = new Person("Alice", 25);
const bob: Person = new Person("Bob", 30);

console.log(alice);   // Person { firstName: 'Alice', age: 25 }
console.log(bob);     // Person { firstName: 'Bob', age: 30 }
```

Из одного класса создано два совершенно разных объекта. Тип данных объекта — имя класса: `alice` имеет тип `Person`.

Это объясняет конструкции, которые встречались раньше: `new Array(...)`, `new Date(...)`. `Array` и `Date` — встроенные классы, а то, что получалось, — объекты этих классов.

---

## 5. Обращение к полям объекта

Через точку, как у обычного объекта:

```ts
console.log(alice.firstName);   // Alice
```

Важная формулировка: мы обращаемся не к классу, а к **объекту, созданному из класса**. С классом работа происходит ровно один раз — в момент `new`. Всё остальное время вы работаете с объектом, и с ним можно делать всё то же, что с любым объектом из прошлых лекций.

## 6. Методы класса

**Метод** — функция внутри класса. Пишется без слова `function`.

### Базовый синтаксис

```ts
class ИмяКласса {
    имяМетода(параметры): ТипРезультата {
        return результат;
    }
}
```

### Пример

```ts
class Person {
    firstName: string;
    age: number;

    constructor(firstName: string, age: number) {
        this.firstName = firstName;
        this.age = age;
    }

    greeting(): string {
        return `Hello, my name is ${this.firstName} and I am ${this.age} years old.`;
    }

    greetCity(city: string): string {
        return `Hello from ${city}, I am ${this.firstName}.`;
    }
}

const alice = new Person("Alice", 25);
console.log(alice.greeting());             // Hello, my name is Alice and I am 25 years old.
console.log(alice.greetCity("Tbilisi"));   // Hello from Tbilisi, I am Alice.
```

Внутри метода `this` работает так же, как в конструкторе: `this.firstName` — поле класса, `city` — аргумент метода. Правило без исключений: **если значение пришло в метод через скобки — пишем просто имя; если это поле класса — пишем `this.имя`.**

Методы могут ничего не возвращать (`void`), принимать несколько аргументов, иметь опциональные параметры и параметры по умолчанию — все правила функций из лекции 5 действуют.

Через `this` можно вызвать и другой метод: `this.имяМетода()`.


## 7. Опциональные параметры конструктора

### Базовый синтаксис

```ts
class ИмяКласса {
    поле: Тип | undefined;
    constructor(параметр?: Тип) {
        this.поле = параметр;
    }
}
```

### Пример

```ts
class Person {
    firstName: string;
    age: number | undefined;

    constructor(firstName: string, age?: number) {
        this.firstName = firstName;
        this.age = age;
    }
}

const withAge = new Person("Alice", 25);
const noAge = new Person("Bob");

console.log(withAge);   // Person { firstName: 'Alice', age: 25 }
console.log(noAge);     // Person { firstName: 'Bob', age: undefined }
```

Ключевой момент, который разбирали на лекции долго: **поле существует всегда**, даже если значение не передали. Класс знает об этом поле; просто его значение — `undefined`. Проверка `"age" in noAge` возвращает `true`.

Зачем это нужно: данные приходят извне — например, из ответа API пришло 5 полей из 15, а остальные придут позже. Объявив поля опциональными, вы заранее описываете все возможные свойства будущего объекта.

Обратите внимание на асимметрию в примере: у поля тип `number | undefined`, а у параметра — `number` со знаком вопроса. Знак вопроса у параметра уже означает «может отсутствовать», дублировать `| undefined` там не нужно. А вот у поля указать `| undefined` важно: без этого любое обращение к полю будет считаться обращением к числу, и ошибка вылезет позже, в месте использования.

**Уточнение.** Если поле объявлено как `age?: number`, использовать его напрямую компилятор не даст:

```ts
describe(): string {
    return `${this.firstName} ${this.age + 1}`;   // ошибка TS2532: Object is possibly 'undefined'
}
```

Перед использованием нужна проверка — та же логика, что с опциональными параметрами функций из лекции 5.

## 8. Параметр по умолчанию

### Базовый синтаксис

```ts
constructor(параметр: Тип = значение) { }
```

### Пример

```ts
class Person {
    firstName: string;
    age: number;

    constructor(firstName: string, age: number = 0) {
        this.firstName = firstName;
        this.age = age;
    }
}

console.log(new Person("Bob"));   // Person { firstName: 'Bob', age: 0 }
```

Разница с опциональным параметром: здесь поле не опциональное, оно обязано быть. Просто если значение не передали, подставится указанное по умолчанию. Проверка внутри класса не нужна — значение есть всегда.

## 9. Поле со значением внутри класса

Поле не обязано получать значение извне. Его можно задать прямо в классе:

```ts
class Person {
    firstName: string;
    email: string = "test@example.com";

    constructor(firstName: string) {
        this.firstName = firstName;
    }
}

const alice = new Person("Alice");
console.log(alice.email);   // test@example.com
```

Такое поле нельзя задать при создании объекта — в конструкторе его просто нет. Но у созданного объекта оно есть и доступно, а если нужно запретить его изменение — см. `readonly` ниже.

Технически значение можно присвоить и внутри конструктора (`this.email = "..."`), но смысла в этом мало: если значение фиксированное, пишите его сразу при объявлении поля.

## 10. Класс и объект: что когда меняется

Вопрос, вокруг которого на лекции был долгий разбор. Разделение простое:

| | Класс | Объект от класса |
|---|---|---|
| Когда работаем | один раз, в момент `new` | всё остальное время |
| Что можно | описать поля, методы, конструктор | менять значения свойств, вызывать методы |
| Переопределить аргументы конструктора | нельзя — они исчезают после его работы | — |

```ts
const alice = new Person("Alice", 25);
alice.firstName = "Alice Smith";   // работаем с объектом — можно
console.log(alice.firstName);      // Alice Smith
```

Менять сам класс после объявления нельзя — лектор отметил, что способ существует, но разбирать его будут на следующем занятии.

## 11. `readonly`

Запрещает менять значение свойства после создания объекта.

### Базовый синтаксис

```ts
class ИмяКласса {
    readonly поле: Тип;
}
```

### Пример

```ts
class Person {
    readonly firstName: string;

    constructor(firstName: string) {
        this.firstName = firstName;
    }
}

const alice = new Person("Alice");
alice.firstName = "Bob";   // ошибка TS2540: Cannot assign to 'firstName'
                           // because it is a read-only property
```

Поле, помеченное `readonly` в классе, становится доступным только для чтения и у объекта.


## 12. `private`

Делает поле или метод невидимым за пределами класса.

### Базовый синтаксис

```ts
class ИмяКласса {
    private поле: Тип;
    private имяМетода(): ТипРезультата { }
}
```

### Пример

```ts
class Employee {
    public firstName: string;
    private salary: number;
    private bonus: number = 500;

    constructor(firstName: string, salary: number) {
        this.firstName = firstName;
        this.salary = salary;
    }

    private getSalary(): number {
        return this.salary + this.bonus;
    }

    public calculateSalary(): string {
        return `I earn ${this.getSalary()}`;
    }
}

const emp = new Employee("Alice", 1000);
console.log(emp.firstName);         // Alice
console.log(emp.calculateSalary()); // I earn 1500
console.log(emp.salary);            // ошибка TS2341: Property 'salary' is private
```

Логика: внутри класса приватные поля и методы видны и используются свободно. Снаружи — нет. Если наружу нужно отдать результат, делается публичный метод, который внутри обращается к приватным данным.

Пример из лекции: зарплату и формулу её расчёта видеть должны не все, а итоговую строку — можно.

**Уточнение (важное для QA).** `private` — конструкция **только TypeScript**. В JavaScript её не существует, и после компиляции поле становится обычным. Это видно сразу:

```ts
console.log(emp);
// Employee { firstName: 'Alice', salary: 1000, bonus: 500 }
```

Приватные поля присутствуют в объекте во время выполнения. `private` защищает от ошибок разработчика на этапе компиляции, но **не скрывает данные в рантайме**. Если тестируете что-то, связанное с безопасностью, помнить об этом обязательно: пометка `private` не означает, что значение недоступно.


## 13. `public`

Противоположность `private`: свойство видно отовсюду.

```ts
class Person {
    public firstName: string;
    private age: number;

    constructor(firstName: string, age: number) {
        this.firstName = firstName;
        this.age = age;
    }
}
```

Если модификатор не указан, свойство **публичное по умолчанию**. Писать `public` явно не обязательно, но чище — так читающему код сразу видно намерение автора.

Понятия «приватный конструктор» на этом уровне нет: конструктор в классе один.

## 14. Короткая запись конструктора

Когда полей много, каждое приходится писать трижды: объявить поле, принять аргумент, присвоить через `this`. TypeScript даёт сокращённую форму.

### Базовый синтаксис

```ts
class ИмяКласса {
    constructor(
        public поле1: Тип,
        private поле2: Тип,
    ) {}
}
```

Модификатор доступа прямо в скобках конструктора автоматически создаёт поле и присваивает ему значение.

### Пример

Было:

```ts
class Person {
    public firstName: string;
    public lastName: string;
    private age: number;

    constructor(firstName: string, lastName: string, age: number) {
        this.firstName = firstName;
        this.lastName = lastName;
        this.age = age;
    }
}
```

Стало:

```ts
class Person {
    constructor(
        public firstName: string,
        public lastName: string,
        private age: number,
    ) {}

    describe(): string {
        return `${this.firstName} ${this.lastName}, ${this.age}`;
    }
}

const ps = new Person("Alice", "Smith", 25);
console.log(ps.firstName);     // Alice
console.log(ps.describe());    // Alice Smith, 25
console.log(ps);               // Person { firstName: 'Alice', lastName: 'Smith', age: 25 }
```

Три момента, которые на лекции уточняли отдельно:

1. **Пустые фигурные скобки `{}` обязательны.** Без них — ошибка `TS2390: Constructor implementation is missing` плюс `TS2369: A parameter property is only allowed in a constructor implementation`.
2. **Модификатор доступа обязателен.** Без `public`/`private` параметр останется обычным аргументом конструктора, и поля не возникнет.
3. При нескольких полях каждое пишут на отдельной строке — так читается лучше; при одном-двух можно в одну строку.

Эта запись используется часто и считается нормой.

## 15. Приватность в JavaScript: `#` и `_`

Раз `private` существует только в TypeScript, в JavaScript применяют другие приёмы.

**`#` — настоящее приватное поле.** Часть стандарта JavaScript, работает в рантайме:

```ts
class Person {
    #age: number;
    constructor(age: number) { this.#age = age; }
    getAge(): number { return this.#age; }
}

const p = new Person(25);
console.log(p.getAge());   // 25
console.log(p);            // Person {}   — поля не видно
```

Сравните с выводом объекта из раздела 12: там приватные поля видны, здесь — нет. Это и есть разница между пометкой компилятора и настоящей приватностью.

**`_` — соглашение, а не защита.** Подчёркивание в начале имени означает «я задумывал это как внутреннее, не трогай снаружи». Технически поле остаётся публичным и прекрасно видно. Пришло из старого кода и встречается до сих пор.

На практике в TypeScript пишут `private`, а `_` используют для приватного поля, стоящего за геттером и сеттером (следующий раздел).

## 16. `static`

Статические поля и методы принадлежат **классу**, а не объекту. В объекте их просто нет.

### Базовый синтаксис

```ts
class ИмяКласса {
    static поле: Тип = значение;
    static имяМетода(параметры): ТипРезультата { }
}

ИмяКласса.имяМетода();   // вызов через имя класса, без new
```

### Пример

```ts
class Car {
    carName: string;
    static dealerName: string = "Best Cars";

    constructor(carName: string) { this.carName = carName; }

    getCarName(): string { return this.carName; }

    static getDealerName(city: string): string {
        return `Dealer of ${city}`;
    }
}

const myCar = new Car("Honda");

console.log(myCar.getCarName());            // Honda — обычный метод, через объект
console.log(Car.getDealerName("Tbilisi"));  // Dealer of Tbilisi — статический, через класс
console.log(Car.dealerName);                // Best Cars
```

Обращение к статическому члену через объект не работает:

```ts
console.log(myCar.dealerName);
// ошибка TS2576: Property 'dealerName' does not exist on type 'Car'.
// Did you mean to access the static member 'Car.dealerName' instead?
```

### Статический метод не видит обычные поля

```ts
class Car {
    carName: string;
    constructor(carName: string) { this.carName = carName; }

    static getDealer(): string {
        return this.carName;   // ошибка TS2339: Property 'carName' does not exist on type 'typeof Car'
    }
}
```

Причина, которую на лекции сформулировали верно: статический метод вызывается без создания объекта. Объекта нет — значит, и значений полей нет, обращаться не к чему.

Если внутри статического метода всё-таки нужны обычные поля, придётся создать там объект самому (`const myCar = new Car("Honda")`). Так почти никогда не делают: нужда в этом обычно означает, что метод не должен был быть статическим.

### Когда нужен `static`

Для служебных вещей, не связанных с конкретным объектом: математические формулы, константы, вспомогательные функции. Классический пример — `Math.max()`, `Math.random()`: вы никогда не пишете `new Math()`, а просто вызываете метод через имя.

### `static` или `readonly`

| | Где живёт | Виден ли объекту |
|---|---|---|
| `readonly` | в объекте | да, но изменить нельзя |
| `static` | в классе | нет, в объекте его не существует |

## 17. Геттеры и сеттеры

### Задача

Класс спокойно принимает мусор:

```ts
const person = new Person("", 500);
console.log(person);   // Person { firstName: '', age: 500 }
```

Пустое имя и возраст 500 физически невозможны, но ничто их не остановило. Геттеры и сеттеры позволяют проверять данные на входе.

- **Сеттер** (`set`) — срабатывает при присваивании значения свойству. Внутри делается проверка.
- **Геттер** (`get`) — срабатывает при чтении свойства. Отдаёт значение наружу.

### Базовый синтаксис

```ts
class ИмяКласса {
    private _поле: Тип = значениеПоУмолчанию;

    get поле(): Тип {
        return this._поле;
    }

    set поле(value: Тип) {      // тип возврата НЕ указывается
        // проверка
        this._поле = value;
    }
}
```

Три имени, которые работают вместе:

1. приватное поле с подчёркиванием — `_firstName`, где реально хранится значение;
2. геттер и сеттер — `firstName`, без подчёркивания;
3. `this.firstName` в конструкторе — обращается не к полю, а к сеттеру.

Имена геттера и сеттера совпадают между собой и совпадают с тем, что вы пишете после `this.` в конструкторе. Подчёркивание есть только у приватного поля.

### Пример

```ts
class Person {
    private _firstName: string = "";
    private _age: number = 0;

    constructor(firstName: string, age: number) {
        this.firstName = firstName;   // уходит в сеттер, а не напрямую в поле
        this.age = age;
    }

    get firstName(): string {
        return this._firstName;
    }

    set firstName(value: string) {
        if (value.length < 2) {
            console.log("Error: first name must have more than 2 characters");
            return;
        }
        this._firstName = value;
    }

    get age(): number {
        return this._age;
    }

    set age(value: number) {
        if (value < 0 || value > 120) {
            console.log("Error: age must be between 0 and 120");
            return;
        }
        this._age = value;
    }
}
```

Корректные данные:

```ts
const good = new Person("John", 25);
console.log(good.firstName);   // John
console.log(good.age);         // 25
```

Мусор:

```ts
const bad = new Person("", 500);
// Error: first name must have more than 2 characters
// Error: age must be between 0 and 120
console.log(bad.firstName);   // ""   — осталось начальное значение
console.log(bad.age);         // 0
```

### Как это работает по шагам

1. Пишем `new Person("John", 25)` — запускается конструктор.
2. Конструктор доходит до `this.firstName = firstName`. Он видит, что есть сеттер с именем `firstName`, и вместо прямой записи в поле передаёт значение в сеттер.
3. Сеттер проверяет значение. Если проверка не прошла — `return`, и запись не происходит.
4. Если прошла — `this._firstName = value`, значение записывается в приватное поле.
5. При чтении `good.firstName` срабатывает геттер и возвращает `this._firstName`.

**`return` в сеттере обязателен.** Без него после вывода ошибки выполнение пойдёт дальше и запишет негодное значение. Альтернатива — `else`.

В реальном коде вместо `console.log` пишут `throw new Error(...)`, чтобы выполнение останавливалось, а не продолжалось с мусором. `console.log` в примере только для наглядности.

### Главное отличие сеттеров в TypeScript

Сеттеру **не указывают тип возвращаемого значения**:

```ts
set firstName(value: string): void {   // ошибка TS1095:
    this._firstName = value;           // A 'set' accessor cannot have a return type annotation
}
```

Ни `void`, ни `never`, ни что-либо ещё — компилятор не хочет видеть там ничего. Лектор отметил, что это частый вопрос на собеседованиях по TypeScript: в чём отличие сеттеров от JavaScript. Отличия два — везде проставленные типы данных и отсутствие аннотации возврата у сеттера.

### Геттеры и сеттеры необязательны для всех полей

Можно сделать их только для тех свойств, которые нужно проверять, а остальные оставить обычными. Короткая запись конструктора (раздел 14) с ними тоже совместима — логика не меняется.

**Уточнение (в лекции сказано неполно).** Прозвучало, что сеттер вызывается автоматически при создании объекта. Это верно, но не полно: сеттер срабатывает при **любом** присваивании свойству, в том числе уже после создания:

```ts
const person = new Person("John", 25);
person.age = 999;           // Error: age must be between 0 and 120
console.log(person.age);    // 25 — значение не изменилось
person.age = 30;
console.log(person.age);    // 30
```

Это делает сеттеры заметно полезнее: проверка защищает объект на всём протяжении жизни, а не только в момент создания.

**Связь с работой QA.** Геттеры и сеттеры — это валидация на входе, а разбор примера с возрастом 500 и пустым именем — ровно анализ граничных значений. Когда будете писать проверки сами, те же вопросы, что при тест-дизайне: что на нижней границе, что на верхней, что за её пределами, что при пустом значении.

# Часть 2. Модули

## 18. Что такое модули

**Модули** позволяют разбивать код на отдельные файлы: объявить функцию, переменную, класс или объект в одном файле, а использовать в другом.

Нужны по простой причине: один файл быстро становится слишком длинным и нечитаемым. Работают одинаково в JavaScript и TypeScript.

---

## 19. Настройка проекта

Чтобы модули заработали, нужны две вещи.

**1. В `package.json` добавить:**

```json
{
    "type": "module"
}
```

**2. Создать `tsconfig.json`** с секцией `compilerOptions` — лектор обещал скинуть готовый файл в чат.

Что это за файлы и как они устроены, разберут на отдельном занятии.

## 20. Именованный экспорт и импорт

### Базовый синтаксис

```ts
// файл-источник
export const имя = значение;
export function имяФункции() { }

// или одним списком в конце файла
export { имя1, имя2, имя3 };

// файл-получатель
import { имя1, имя2 } from "./путь-к-файлу";
```

Имена в фигурных скобках при импорте должны совпадать с именами при экспорте — отсюда название «именованный».

### Пример

Файл `exports.ts`:

```ts
export const name1: string = "John";

export function myFunction(): string {
    return "Hello from function";
}

const lastName: string = "Smith";
const age: number = 25;
export { lastName, age };     // список в конце файла
```

Файл `imports.ts`:

```ts
import { name1, myFunction, lastName } from "./exports";

console.log(name1);          // John
console.log(myFunction());   // Hello from function
console.log(lastName);       // Smith
```

Экспортировать можно практически что угодно: переменные, функции, объекты, классы.

Два способа — помечать каждое объявление словом `export` или собрать всё в один список в конце файла — равнозначны. Список чаще используют, когда в файле много функций.

---

## 21. Экспорт по умолчанию

### Базовый синтаксис

```ts
// файл-источник
export default значение;

// файл-получатель — без фигурных скобок, имя любое
import любоеИмя from "./путь-к-файлу";
```

### Пример

```ts
// exports.ts
export default function mainThing(): string {
    return "I am the default export";
}
```

```ts
// imports.ts
import whateverIWant from "./exports";

console.log(whateverIWant());   // I am the default export
```

Два отличия от именованного экспорта: фигурных скобок при импорте нет, и имя при импорте можно выбрать любое — именно потому, что при экспорте оно не задавалось.

**Экспорт по умолчанию в файле может быть только один.** Попытка написать второй даёт ошибку `TS2528: A module cannot have multiple default exports`.

Именованный и экспорт по умолчанию можно совмещать в одном файле, но смешивать их в одном импорте следует аккуратно — лектор на этом не останавливался.

## 22. Переименование через `as`

Имя, под которым что-то экспортировали, может ничего не говорить в вашем коде. Его можно переименовать при импорте.

### Базовый синтаксис

```ts
import { оригинальноеИмя as новоеИмя } from "./файл";
```

### Пример

```ts
import { name1 as customName, myFunction as customFunction } from "./exports";

console.log(customName);          // John
console.log(customFunction());    // Hello from function
```

Зачем: файл мог писать кто-то другой, и его имена для вашего кода бессмысленны. Переименование делает код понятнее — в том числе вам самим через год.

Для экспорта по умолчанию `as` не нужен: имя там и так выбирается свободно при импорте.

---

## 23. Что когда использовать

**Именованный экспорт** — когда в файле много переменных, функций или объектов, и нужно экспортировать их все. Типичный случай — utility-файл с набором функций, а также библиотеки: сторонний код почти всегда использует именно его.

Преимущества, названные на лекции:

- VS Code лучше работает с именованными экспортами — по имени понятно, что импортируется, проще находить неиспользуемый код;
- есть выигрыш в производительности сборки;
- большинство компаний сегодня используют именно именованные экспорты, а экспорт по умолчанию ограничивают или запрещают настройками линтера.

**Экспорт по умолчанию** — когда в файле ровно одна сущность: один класс, один компонент (кнопка, ссылка, картинка). Внутри может быть много логики, но наружу отдаётся одна вещь.

Практический вывод: **экспорт по умолчанию всегда заменяется именованным**, обратное не всегда удобно. Многие компании заставляют переписывать default на именованные, и когда таких мест сотни, это недели работы. Начинать сразу с именованных дешевле.

**Связь с работой QA.** Классы и модули — та пара, на которой строится Page Object Model: каждая страница описывается классом в своём файле и экспортируется, а тест этот класс импортирует. Это прямой мост ко второй половине курса, где начнётся Playwright.

## 25. Шпаргалка и типичные ошибки

### Синтаксис на одной странице

```ts
// класс, поля, конструктор, метод
class Person {
    firstName: string;
    private age: number;
    readonly id: string = "001";
    static counter: number = 0;

    constructor(firstName: string, age: number) {
        this.firstName = firstName;
        this.age = age;
    }

    greeting(): string {
        return `Hello, ${this.firstName}`;
    }

    static describe(): string {
        return "Класс Person";
    }
}

const alice = new Person("Alice", 25);
alice.greeting();        // через объект
Person.describe();       // статический — через класс

// короткая запись конструктора
class Short {
    constructor(
        public firstName: string,
        private age: number,
    ) {}
}

// геттер и сеттер
class WithCheck {
    private _age: number = 0;

    get age(): number {
        return this._age;
    }

    set age(value: number) {           // без типа возврата
        if (value < 0) { return; }
        this._age = value;
    }
}

// модули
export const name1: string = "John";          // именованный
export { lastName, age };                     // именованный списком
export default function main() { }            // по умолчанию, один на файл

import { name1, lastName as custom } from "./file";
import whateverName from "./file";
```

### Модификаторы и их действие

| Что | Где видно | Можно менять снаружи | Существует в рантайме |
|---|---|---|---|
| без модификатора / `public` | везде | да | да |
| `private` | только внутри класса | нет (ошибка компиляции) | **да** — поле видно в объекте |
| `#` | только внутри класса | нет | нет — настоящая приватность |
| `_` | везде | да | да — это просто соглашение |
| `readonly` | везде | нет | да |
| `static` | только через имя класса | да | да, но в классе, не в объекте |

### Три части, которые путают

| Запись | Что это |
|---|---|
| `firstName` в скобках конструктора | аргумент, пришёл извне, живёт только внутри конструктора |
| `this.firstName` | поле класса, станет свойством объекта |
| `_firstName` | приватное поле за геттером и сеттером |

### Частые ошибки

1. **Забыть `this`** при обращении к полю внутри метода — код возьмёт аргумент или вообще ничего не найдёт.
2. **Забыть `new`** при создании объекта — конструктор не запустится.
3. **Забыть пустые `{}`** после короткой записи конструктора — ошибка TS2390.
4. **Забыть модификатор доступа** в короткой записи — поле не создастся, останется обычный аргумент.
5. **Указать тип возврата у сеттера** — ошибка TS1095, компилятор его там не допускает.
6. **Забыть `return` в сеттере после проверки** — негодное значение всё равно запишется.
7. **Обратиться к статическому члену через объект** — его там нет, нужно имя класса.
8. **Использовать `this.поле` в статическом методе** — объекта не существует, обращаться не к чему.
9. **Не инициализировать поле** ни при объявлении, ни в конструкторе — ошибка TS2564, и касается она не только приватных полей.
10. **Считать `private` защитой данных** — в рантайме поле видно, это подсказка компилятора, а не безопасность.
11. **Сделать два `export default` в одном файле** — ошибка TS2528.
12. **Перепутать фигурные скобки при импорте** — они нужны для именованного экспорта и не нужны для экспорта по умолчанию.
